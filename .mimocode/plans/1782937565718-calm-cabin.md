# Plan: Sistema de Importación/Exportación CSV Unificado

## Problemas actuales

1. **4 tarjetas separadas** — usuario debe elegir tipo por separado
2. **Sin validación de columnas** — CSV incorrecto crea registros vacíos
3. **FK por título** — cambio de título = importación falla silenciosamente
4. **Sin upsert** — duplicados ignorados, imposible actualizar vía CSV
5. **Sin transacciones** — fallo a mitad deja datos parciales
6. **Contador de quiz engañoso** — mezcla quiz + preguntas
7. **Sin validación de enums** — `tipo` acepta cualquier string
8. **Sin auto-detección** — usuario debe saber qué tipo sube

## Solución: CSV Unificado + Panel Único

### CSV Unificado — Formato para IA y humanos

**Principio:** Un solo CSV con columna `tipo` que indica qué es cada fila. Cualquier IA (Claude, ChatGPT, etc.) puede generar el CSV llenando las columnas correspondientes al tipo.

**Columnas del CSV unificado:**

```
tipo, id, modulo_id, modulo_titulo, aula_id, aula_titulo, titulo, descricao, ordem, 
obrigatorio, autoCertificado, videoUrl, pdfUrl, tipo_aula, duracaoMin, videoInicio, 
videoFim, conteudo, inicioSeg, fimSeg, quiz_titulo, notaMinima, pergunta_id, pergunta, 
opcaoA, opcaoB, opcaoC, opcaoD, correta
```

**Filas por tipo:**

| `tipo` | Columnas usadas | Columnas ignoradas |
|--------|-----------------|-------------------|
| `curso` | `titulo`, `descricao`, `ordem`, `obrigatorio`, `autoCertificado`, `videoUrl`, `videoInicio`, `videoFim` | Las demás vacías |
| `aula` | `modulo_id` o `modulo_titulo`, `titulo`, `descricao`, `tipo_aula`, `videoUrl`, `pdfUrl`, `obrigatorio`, `duracaoMin`, `videoInicio`, `videoFim` | Las demás vacías |
| `licao` | `modulo_id`/`modulo_titulo`, `aula_id`/`aula_titulo`, `titulo`, `tipo_aula`, `conteudo`, `duracaoMin`, `inicioSeg`, `fimSeg` | Las demás vacías |
| `quiz_pergunta` | `modulo_id`/`modulo_titulo`, `aula_id`/`aula_titulo`, `quiz_titulo`, `notaMinima`, `autoGerarCertificado`, `pergunta`, `opcaoA`, `opcaoB`, `opcaoC`, `opcaoD`, `correta` | Las demás vacías |

**Ejemplo de CSV que una IA puede generar:**

```csv
tipo,id,modulo_id,modulo_titulo,aula_id,aula_titulo,titulo,descricao,tipo_aula,conteudo,pergunta,opcaoA,opcaoB,opcaoC,opcaoD,correta
curso,,,"Seguridad Vial",,,,,,,,,
aula,,<uuid-mod>,,,"Introducción","Primera aula",VIDEO,,,,,,,,
licao,,<uuid-mod>,,<uuid-aul>,,"Conceptos básicos",,TEXTO,"Contenido aquí",,,,,,
quiz_pergunta,,<uuid-mod>,,<uuid-aul>,,,,,"¿Cuál es la velocidad máxima?",60 km/h,80 km/h,100 km/h,120 km/h,A
```

### Cambio 1: Backend — Endpoint unificado

**Archivo:** `server/routes/import-export.ts`

#### 1a. `POST /api/import-export/detect`
- Recibe `{ csv }` 
- Parsea headers, detecta `tipo` por columna presente
- Retorna `{ type, columns, rowCount, missingRequired, valid, preview }`
- `preview` = primeras 3 filas parseadas para que el frontend muestre

**Detección automática:**
- Si header incluye `tipo` → CSV unificado, leer tipo de cada fila
- Si NO incluye `tipo` → detectar por headers (compatibilidad con CSVs antiguos):
  - Tiene `pergunta` → quiz
  - Tiene `aula_titulo` sin `pergunta` → licoes
  - Tiene `modulo_titulo` sin `aula_titulo` → aulas
  - Solo `titulo` → cursos

#### 1b. `POST /api/import-export/import`
- Recibe `{ csv, mode: "create" | "upsert" }` (mode default = "create")
- Si CSV unificado (tiene `tipo`): procesa cada fila según su tipo
- Si CSV de tipo único: procesa como antes pero con validaciones mejoradas
- **Orden de procesamiento:** cursos → aulas → licoes → quiz (respetando FKs)
- **IDs como FK principal:** si `modulo_id` está presente, úsalo directamente; si no, buscar por `modulo_titulo`
- **Validaciones por fila:**
  - `tipo_aula` ∈ {VIDEO, PDF, TEXTO} — si inválido, error en esa fila
  - `correta` ∈ {A, B, C, D} — default "A" si vacío
  - `notaMinima` numérico 0-100
  - Campos numéricos realmente numéricos
- **Resultado:** `{ created, updated, skipped, total, errors: [{ row, field, message }] }`
- **Transacción:** envolver cada tipo en su propia transacción (no una global, para permitir import parcial por tipo)
- **Log:** `logActivity` con resumen

#### 1c. `GET /api/import-export/export/all`
- Exporta CSV unificado con TODOS los datos
- Incluye columna `tipo` + todos los IDs (`id`, `modulo_id`, `aula_id`, `quiz_id`)
- Un solo archivo descargable

#### 1d. Modificar exports individuales existentes
- Agregar `id`, `modulo_id`, `aula_id` donde corresponda
- Mantener endpoints existentes como fallback

### Cambio 2: Frontend — Panel unificado

**Archivo:** `src/pages/CMSPage.tsx`

Reemplazar las 4 tarjetas por un panel con:

```
┌──────────────────────────────────────────────────┐
│  Importar / Exportar Dados            [Fechar]   │
├──────────────────────────────────────────────────┤
│                                                   │
│  [Exportar Tudo (CSV)]  [Export Individual ▾]     │
│                                                   │
│  ── Importar CSV ──                               │
│                                                   │
│  [Selecionar arquivo .csv...]                     │
│                                                   │
│  ┌─ Preview ──────────────────────────────────┐   │
│  │ Tipo detectado: [curso/aula/licao/quiz/...] │   │
│  │ Colunas: [titulo, descricao, ...]           │   │
│  │ Linhas: 42                                  │   │
│  └────────────────────────────────────────────┘   │
│                                                   │
│  Modo: (●) Apenas criar  ( ) Criar ou atualizar  │
│                                                   │
│  [Importar]                                       │
│                                                   │
│  ── Resultado ──                                  │
│  Criados: 40 | Ignorados: 2 | Erros: 0           │
│                                                   │
│  Dica: Use "Exportar Tudo" para obter o formato   │
│  correto. Qualquer IA pode preencher o CSV.       │
└──────────────────────────────────────────────────┘
```

**Flujo del usuario:**
1. Click en "Importar/Exportar" → se abre el panel
2. Para exportar: un botón "Exportar Tudo" descarga CSV unificado con IDs
3. Para importar: selecciona archivo → frontend muestra preview (tipo, columnas, filas)
4. Elige modo (create por defecto)
5. Click "Importar" → resultado detallado

**Preview en frontend (sin llamar al backend):**
- Leer el archivo como texto
- Parsear primera línea (headers)
- Detectar `tipo` de la columna o por headers
- Contar filas
- Mostrar info al usuario antes de enviar

## Verificación

1. `pnpm dev` → CMS → panel unificado visible
2. Exportar CSV unificado → verificar que incluye `tipo`, IDs, todos los campos
3. Subir CSV unificado → auto-detección muestra tipo correcto en preview
4. Importar con modo "create" → solo crea nuevos
5. Importar con modo "upsert" → crea o actualiza
6. Importar CSV con columnas incorrectas → errores de validación por fila
7. Importar CSV antiguo (sin `tipo`) → detección por headers funciona
8. `npx tsc --noEmit` typecheck OK
9. `pnpm lint` OK
